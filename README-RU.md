# Usage Meter — ChatGPT, Claude, Gemini, Grok · 0.3.6

Тестовое расширение для Chrome/Chromium 120+. Использует текущие сессии сайтов; отдельные приложения, API-ключи и CLI не нужны. Grok включён; платная ветка экспериментальная. Perplexity не включён.

## Изменения 0.3.5

- Типографика виджета приближена к образцу: ширина 280 px, системный sans-serif, заголовок 13 px, подписи квот 12 px, даты сброса 10 px и более выраженные числовые значения. Интервалы Feature limits уменьшены. Сохраняются used/left и три уровня сворачивания. Popup, его размеры, шрифты и прежняя палитра не изменены.
- Цвет заполнения полос виджета плавно меняется от зелёного через янтарный к красному. Цифры в виджете и свёрнутой строке становятся жёлтыми при 70% израсходованного и красными при 90%. Цвет текста адаптирован к светлой/тёмной теме.
- Для квот с одним остатком сохраняется максимальный наблюдавшийся остаток отдельно по проверенному аккаунту и тарифу. Это локальный ориентир для цвета, не подтверждённая общая квота; он указан в подсказке числа. Порог считается с округлением вниз в единицах израсходованного: при ориентире 5 остаток 2 жёлтый, 1 и 0 красные. Ноль всегда красный. Первое ненулевое наблюдение без истории остаётся нейтральным; проценты для этих квот не выдумываются.
- При смене тарифа ориентир начинается заново; перезапуск worker его сохраняет. Схемы запросов и получение данных не менялись.
- Добавлены актуальный английский README, .gitignore и регрессионные проверки интерфейса/адаптеров. Устаревшие worker-тесты заменены актуальными.

## Исправления 0.3.4

- Исправлен подтверждённый сетевой сбой: 18 октября 2026 публичный GraphQL-запрос с `authuser=0` вернул HTTP 302 на тот же endpoint без этого параметра. Прежний `redirect: error` превращал его в TypeError. Теперь разрешено следование перенаправлению с проверкой конечного домена, маршрута, query_signature, variables и индекса аккаунта. Потерять индекс можно только для аккаунта 0; остальные случаи отклоняются. Bootstrap-проверки до и после чтения сохранены.
- Новый начальный источник дескриптора: import map обычной вкладки `/app` → конкретный публичный `UsagePageSurface-*.js` → Relay `params.id` точной операции `UsagePageQuery` → прямой JSON. Для этого не нужны отображение полос, открытие настроек, iframe или предыдущий перехват запроса. При отсутствии import map запрашивается анонимная HTML-оболочка `/usage` только для поиска ссылки на модуль. Сам HTML не считается источником квот.
- На публичных Google-ресурсах проверены оба бандла, `full/client` и `islands`: в них отсутствует поле query_signature, а подпись лежит в Relay params.id. На дату проверки она совпадала с константой старых версий; утверждение, что эта константа протухла, не подтвердилось. Подпись в 0.3.4 обнаруживается динамически, а не задаётся новой константой.
- Разбирается только небольшой дескриптор с именем UsagePageQuery; неоднозначность отклоняется. Допускаются только соответствующие публичные модули на www.gstatic.com. Исходники читаются как текст и не выполняются. На запросах к CDN и публичной оболочке явно стоят credentials: omit. Google отдаёт проверенный модуль с CORS для origin Gemini, поэтому новых host permissions не добавлено.
- Отказ кешированного дескриптора сначала вызывает повторное обнаружение в текущем клиенте и повтор прямого JSON. Только затем используются перехват штатной страницы и DOM. Сбой загрузки метаданных имеет отдельную задержку повторов, ручное обновление может повторить обнаружение раньше.
- Если JSON-запрос из вкладки получает сетевую ошибку, выполняется один GET через service worker с браузерными cookies и тем же явно выбранным индексом аккаунта. Значения cookies не извлекаются и не сохраняются. HTTP 429 через второй транспорт не повторяется. Конечный адрес также проверяется.
- Диагностика различает обнаружение Relay-дескриптора, JSON и штатный Usage-зонд. Интерфейс сохранён.

**Предел проверки:** публичные ресурсы Google и анонимный GraphQL/302 проверены непосредственно. Получение числовых квот из авторизованной сессии пользователя в этой среде не проверялось. Начальное чтение без Usage-страницы, смена подписи и привязка аккаунта проверены в браузере на контролируемых HTTP-ответах.

Заголовки, cookies, полные URL и произвольные переменные не сохраняются. authuser и маршрут пересобираются под текущий аккаунт; используется тот же вид пути, который наблюдался в рабочем запросе.

При отказе выполняется новый захват; недавний перехват старой подписи и старый DOM открытой Usage-страницы не используются для восстановления подписи. DOM остаётся резервным источником. Нет гарантированного времени ответа или гарантии, что Google разрешит iframe в каждой конфигурации.

- Отсутствующая bootstrap-идентичность iframe означает ожидание проверки, а не мгновенное несовпадение аккаунта. Пустая идентичность не разрешает принять данные. Несовпадающий аккаунт по-прежнему отклоняется.
- Парсер ищет именованные usage pools в ограниченной глубине оболочек JSON; TIER2 отображается как Ultra. percentageUsed по поддерживаемой схеме является долей 0..1: 1 означает 100%. Изменение единиц не угадывается по величине числа.
- Диагностика неудачного зонда показывает, установлен ли bridge, число совпавших RPC, HTTP-статус и этап разбора. Чужие поля ответа отбрасываются; исходный ответ страницы сохраняется для штатного клиента. Наблюдатель сам отключается без продления lease; после обновления расширения его можно установить повторно.
- При обновлении сбрасываются старые задержки Gemini. Интерфейс и поведение остальных провайдеров сохранены.

- Привязки вкладок восстанавливаются из `chrome.storage.session` внутри инициализации worker. Тик значка не запускает повторный опрос всех вкладок. В session хранится только текущая привязка контекста в памяти браузера, не cookies; local-кеш по-прежнему содержит только хеши и нормализованные квоты.
- SPA-переход внутри того же провайдера и Google-аккаунта сохраняет виджет и значок. Переход на другой сайт или индекс Google-аккаунта очищает привязку. Ключ закрытой вкладки удаляется из карты ожидающих привязок.
- Статус ошибки показывает время последнего успешного чтения. Успешное новое чтение очищает прежнюю ошибку; реальная последующая неудача остаётся видимой. Текст `Copied` возвращается к `Copy diagnostics` через две секунды.

**Из замечаний Argon намеренно не применено возвращение Feature limits в popup:** по согласованному ТЗ popup содержит полосы usage, а дополнительные квоты находятся в полном виджете и настройках.

## Установка и обновление

1. Распакуйте ZIP в постоянную папку.
2. Для обновления замените содержимое **прежней папки `extension`**, сохранив её путь. Затем нажмите кнопку обновления расширения в `chrome://extensions`. Настройки сохранятся. Загрузка из другой папки может создать отдельный экземпляр расширения.
3. При первой установке включите «Режим разработчика», нажмите «Загрузить распакованное расширение» и выберите папку `extension`, где находится `manifest.json`.
4. Разрешите доступ к `chatgpt.com`, `claude.ai` и `gemini.google.com`. В 0.3.0 также добавлено разрешение `cookies`, необходимое для проверки смены сессии Claude.
5. Откройте нужный чат и закрепите расширение на панели. Popup показывает провайдера активной вкладки. Виджет включается шестерёнкой → Floating widget; по умолчанию он выключен.

Включение виджета внедряет его в уже открытые вкладки. Обычно перезагрузка страницы не нужна. После обновления расширения или изменения разрешений при необходимости обновите вкладку один раз. Отключите предыдущие сторонние трекеры, если они создают дополнительные панели.

## Интерфейс

- Заголовки popup и полного виджета: **ChatGPT Usage**, **Claude Usage**, **Gemini Usage**.
- Popup и значок относятся к активной вкладке текущего окна. Виджет каждой вкладки показывает её собственный контекст; переключение на другой сервис его данные не меняет.
- На других сайтах значок остаётся **без процентов**, а popup предлагает открыть поддерживаемый чат. Публичные ссылки Share и служебные API/страницы входа исключены. Настройки/страницы Usage внутри поддерживаемых сервисов относятся к их контексту аккаунта.
- Popup: used слева, left справа, время до сброса. Виджет: те же числа, дата и время сброса.
- **Used / Left** в отдельном экране настроек меняет только значок. Значок чередует основные пятичасовое и недельное окна приблизительно раз в 30 секунд. Отсутствующие окна не создаются.
- В виджете цвет полос меняется плавно, цифровые значения предупреждают от 70% и становятся красными от 90%. У popup и значка сохранена прежняя палитра. Серый значок означает устаревшие данные или наступивший срок сброса. После срока сброса значения не обнуляются без ответа сервера.
- Виджет имеет три состояния: все доступные квоты → полосы usage → компактная строка. В строке указан провайдер; `5h 24 / 76%` означает 24% used и 76% left.
- Перетаскивание, сворачивание и выключение работают без перезагрузки. Режим, положение и включение виджета пока общие для трёх провайдеров.
- Светлая/тёмная тема виджета следует за страницей; popup использует тему активной поддерживаемой вкладки, иначе системную.
- Для отдельной возможности с известным только остатком выводится `N left`; общий лимит и проценты не выдумываются.

## Источники

### ChatGPT

GET `/api/auth/session`, GET `/backend-api/wham/usage`, POST `/backend-api/conversation/init` с `conversation_id: null` и без сообщения пользователя. Сохраняются прежние workspace-проверки, передача `chatgpt-account-id` и отдельные квоты возможностей. Токен используется только в памяти. Free-процент Work/Codex не является счётчиком всех сообщений Chat.

### Claude

GET `/api/organizations`, затем GET `/api/organizations/{org_uuid}/usage` в существующей вкладке. Организация берётся из `lastActiveOrg` и проверяется по `capabilities: chat`. Если cookie отсутствует, автоматически выбирается только единственная chat-организация; несколько организаций без определённого выбора вызывают ошибку контекста.

Отображаются `five_hour`, `seven_day`, дополнительные заполненные окна, включая Sonnet/Opus, и `limits[]` с видами session/weekly_all/weekly_scoped. При наличии серверного процента показывается Extra usage. Для иконки используются основные пятичасовое и недельное окна.

Разрешение cookies используется **только для чтения `sessionKey` на claude.ai**. Значение не сохраняется, не меняется и не выводится в журнал. Хеш сессии разделяет кеш разных пользователей одного workspace; сессия проверяется до и после получения usage. Org UUID и другие исходные идентификаторы не записываются в хранилище.

### Gemini Web

Первый запрос не зависит от перехвата или отображения настроек. Из import map страницы `/app` определяется публичный модуль `UsagePageSurface-*.js` (full/client или islands). При отсутствии ссылки во вкладке можно прочитать анонимную HTML-оболочку `/usage`. Из модуля текстовым разбором Relay-дескриптора извлекается `params.id` операции `UsagePageQuery`. В модуле не ищется произвольная строка, похожая на хеш. Исходники не выполняются, cookies на CDN не отправляются.

Далее выполняется GET `/_/BardChatUi/graphql/schemas/GEMINI_WEB_GRAPHQL/executeQuery` с явным индексом аккаунта и известными переменными. Результат `viewer.rpcs.getUsageInfo.pools` содержит пятичасовое и недельное окна, percentageUsed (доля × 100), время сброса и код подписки. Подтверждённый дескриптор кешируется отдельно по аккаунту. При отказе выполняется новое обнаружение до обращения к iframe.

Номер аккаунта учитывается по `/u/N/` или числовому authuser. Для прямого чтения проверяется bootstrap `/app` выбранного аккаунта до и после получения JSON. Перенаправление допустимо только при сохранении ожидаемого контекста и параметров запроса. Отсутствие индекса на конечном root-маршруте разрешено только аккаунту 0. Email хешируется внутри страницы и не сохраняется.

Резервные источники: ранний fetch/XHR-перехват штатного Usage-запроса внутри служебной страницы и, если JSON не получен, чтение числовых полос. Их проверка аккаунта сохранена. Неизвестные значения не становятся нулями; служебный iframe удаляется при успехе и ошибке. Нативный Robin GetUsageInfo и квоты Gemini CLI в этот адаптер не входят: у них другая аутентификация/семантика. Публичный Google API здесь не используется; это внутренний endpoint веб-клиента.

TIER1 отображается как Pro, TIER2 — как Ultra; остальные коды не интерпретируются. Число оставшихся промптов не вычисляется из процентной квоты. Расширение не отправляет сообщения и не вызывает модель ради лимитов.

## Обновления и несколько вкладок

Один координатор на контекст объединяет одновременные обновления. Значения поступают только из запросов расширения; вкладки не отправляют в фон собственные числа usage. Нормализованные сетевые перехваты также считываются координатором. Кеш разделён по провайдеру и аккаунту; старые и новые ответы не перезаписывают данные другой вкладки.

Периодический опрос — раз в 5 минут **при наличии открытой поддерживаемой вкладки**. Для тяжёлого DOM-источника Gemini автоматический интервал составляет 10 минут; ручное обновление доступно раньше. Возврат во вкладку, открытие popup и обнаруженное завершение генерации могут запросить обновление. Обычные запросы ограничены одним в минуту, ручные — одним в 15 секунд. Сетевые ошибки используют увеличивающуюся задержку; HTTP 429 не обходится ручным обновлением. Ошибка возможностей ChatGPT не блокирует свежие основные проценты.

Прямой запрос Claude выполняется внутри существующей вкладки с её cookies. Gemini сначала запрашивает JSON из вкладки; при сетевой ошибке доступен один запрос через worker с тем же индексом аккаунта. Только резервный путь Gemini использует служебный iframe страницы Usage. Переключение активной вкладки немедленно выбирает её контекст. Значок задаётся отдельно для каждой вкладки: ответ фонового запроса другого провайдера не может заменить его проценты. Переход на сторонний сайт очищает значок. Между рабочими окнами браузера контекст также переключается.

В одном профиле браузера cookie Claude/ChatGPT может быть общей для вкладок. Расширение проверяет фактический контекст и не создаёт независимые логины в отдельных вкладках. Независимые профили имеют независимое хранилище расширения. Для инкогнито предусмотрен split-контекст, если пользователь разрешил расширение в инкогнито.

## Данные и разрешения

- `storage`: настройки и нормализованный кеш локально.
- `alarms`: расписание опроса и чередования окон.
- `scripting`: запросы в существующих вкладках, определение контекста и включение виджета без обновления страницы.
- `cookies`: проверка смены сессии Claude; запись/удаление cookies не выполняются.
- Доступ только к трём указанным доменам. Нет доступа ко всем сайтам, аналитики, внешних серверов или загружаемого исполняемого кода.

Расширение не извлекает и не сохраняет текст переписки. Claude bridge читает копии SSE/Connect-кадров и выделяет только записи usage; остальные поля не передаются расширению. Для контекста используются cookie выбора workspace или метаданные bootstrap страницы. В хранилище находятся нормализованные квоты, хеши контекстов, ID открытых вкладок и подтверждённый дескриптор Gemini usage-запроса, без email, токенов, исходных ответов и истории URL.

## Проверки и ограничения

Внутренние endpoints могут измениться; ошибка авторизации, отсутствие данных или изменение схемы не преобразуются в нулевой расход. Новые Claude/Gemini-адаптеры реализованы по открытым исходникам и форматам ответов; **живые сессии пользователя в этой среде не проверялись**. Особенно важно проверить маршрутизацию дополнительных Google-аккаунтов и bootstrap-идентичность в вашем браузере. Ошибка контекста блокирует отображение процентов вместо подстановки аккаунта по умолчанию.

При отключении расширения виджет удаляет себя после обнаружения недоступного контекста. В приостановленной вкладке очистка может задержаться до её активации; обновление страницы удаляет панель.

Автоматические проверки на синтетических данных, Node.js 20+, без зависимостей:

```sh
node --test tests/*.test.mjs
```

Проверяются ChatGPT Business/Free, Claude/Gemini, XSSI и дробные проценты, неизвестные и нулевые квоты, выбор организации, смена пользователя во время запроса, несколько Google-аккаунтов, общие запросы нескольких вкладок, отложенные ответы, раздельные значки, пустой значок на других сайтах, рестарт worker, задержки повторов и отсутствие токенов в кеше.

Браузерный тест использует Playwright, Chromium и имитацию Chrome API:

```sh
node tests/ui.browser.cjs
node tests/widget.browser.cjs
node tests/data.browser.cjs
node tests/gemini-network.browser.cjs
node tests/gemini-discovery.browser.cjs
node tests/gemini-redirect.browser.cjs
```

Можно задать `METER_PLAYWRIGHT_MODULE` и `METER_CHROMIUM_PATH`. Это зависимости только тестов. UI-тест проверяет заголовки трёх провайдеров, независимые виджеты, активный popup, три уровня сворачивания, тему, DOM/фокус, перетаскивание, повторное внедрение и popup на сторонней вкладке.

После установки сравните числа со страницами Usage каждого сервиса, переключите три вкладки и затем обычный сайт. Проверьте включение виджета без перезагрузки и, если используете несколько Google-аккаунтов, отдельные `/u/0/` и `/u/1/`. Для диагностики достаточно названия сервиса и текста ошибки; cookies и заголовки авторизации не нужны.

Тест data.browser.cjs воспроизводит HTTP 404 GraphQL с переходом к штатным полосам Gemini, дополнительный Google-аккаунт, нулевой процент, задержанную разметку, несовпадение аккаунта и удаление iframe. Для Claude проверяются реальные Response/ReadableStream в Chromium: SSE, ответ об исчерпании квоты, бинарные и gzip Connect-кадры, сохранность оригинального ответа, отсутствие дополнительных запросов модели и текста сообщений в результате. Живые аккаунты в этих проверках не используются. Схемы внутренних API и потоков могут измениться.

Форматы Claude message_limit/StreamTimeline сверены с открытым проектом kr7shnasomani/claude-token-counter (MIT); реализация ограничена сбором квот и не включает подсчёт токенов, чтение дерева разговора или экспорт чатов.

Тест gemini-network.browser.cjs устанавливает bridge до скриптов синтетических документов и проверяет ранний fetch/XHR во фрейме без полос, повторный прямой запрос, смену подписи, неизменность ответа штатного клиента, отсутствие посторонних полей в результате, отказ при чужом/неопределённом аккаунте и удаление iframe. Это проверка механизма перехвата, не подтверждение работы живого сервера Google.

Тест gemini-discovery.browser.cjs проверяет холодный запуск из /app, получение Relay-дескриптора и JSON без native Usage-зонда, отсутствие выполнения кода CDN, анонимный HTML-fallback, смену подписи, сетевой отказ модуля и смену аккаунта. gemini-redirect.browser.cjs через локальный HTTP-сервер воспроизводит прежний TypeError при redirect:error, успешное чтение после 302 и отказ при потере ненулевого индекса. Для последнего теста подменяется только проверяемое hostname, чтобы использовать локальный сервер; логика функции и browser fetch остаются исходными.
